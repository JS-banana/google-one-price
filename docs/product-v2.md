# v2 产品规范：跨区订阅决策器

> 本文定义 v2 的产品范围、计算规则与页面结构，是 v2 UI 实现的依据。视觉系统沿用 `docs/design.md` §7（色彩、字体、数字排版、组件形态），本文与 `design.md` 冲突时以本文为准。

## 1. 定位

**帮中文用户算清：在哪个区、用哪种方式订 Google One / Gemini，真正最省、买得到、不踩坑。**

v1 回答的是"每个 SKU 在各区多少钱"（表格浏览）。v2 回答的是"按我的情况，我该怎么订"（决策）。表格类能力保留，降级为"全量比价"工具。

差异化（相对 appstoreprice.org 这类通用比价站）：真实持有成本（首期优惠 + 续费 + 账期）、新老订阅资格、家庭分摊、付款可行性。

## 2. 用户与决策

| 用户                 | 要做的决定                         | v2 如何回答                              |
| -------------------- | ---------------------------------- | ---------------------------------------- |
| 短期尝鲜（1–3 个月） | 最少花多少钱先用上，怎么不被续费坑 | 决策器选 3 个月；"首付最低"卡 + 续费警示 |
| 长期自用（1–2 年）   | 去哪区、月付还是年付               | 决策器选 12/24 个月；按总成本排序        |
| 家庭分摊（2–6 人）   | 人均多少，值不值得去低价区         | 人数输入，人均价；家庭共享规则提示       |
| 已订阅/想换区        | 换区一年能省多少                   | "已订阅过"（不计首期优惠）+ 对比基准     |
| 价格研究者           | 全量数据、变动                     | 全量比价、国家页、数据与更新             |

## 3. 方案决策器（首页核心）

### 3.1 输入（全部有默认值，首屏即出结果）

| 参数                     | URL key | 取值                                                                       | 默认  |
| ------------------------ | ------- | -------------------------------------------------------------------------- | ----- |
| 我要什么                 | `need`  | `plus` / `pro` / `ultra` / `storage`                                       | `pro` |
| 存储容量（仅 `storage`） | `cap`   | 数据中实际存在的纯存储容量，如 `100gb` / `200gb` / `2tb` / `10tb` / `20tb` | `2tb` |
| 用多久                   | `m`     | `3` / `12` / `24`（月）                                                    | `12`  |
| 订阅身份                 | `elig`  | `new`（首次订阅，可享首期优惠）/ `existing`（订阅过，不计首期优惠）        | `new` |
| 人数                     | `n`     | `1`–`6`                                                                    | `1`   |
| 只看礼品卡可用地区       | `easy`  | `0` / `1`                                                                  | `0`   |
| 对比基准                 | `base`  | 任一 ISO3                                                                  | `USA` |

参数同步到 URL（`replaceState`），并记忆到 localStorage；URL 优先。

### 3.2 候选集

- 候选 = 所选 `need` 对应商品的**全部活跃报价**（不再按 14 个档位拆分）。**不得复用 `quoteLine()` 的兜底归类**（它把所有非 AI 报价都归入存储），而是在数据层新增显式的 need → SKU/容量映射（单一定义，带测试）：
  - `plus`：Google AI Plus（400 GB）各 SKU。`AI Plus (2 TB)` 不纳入（不同商品）。
  - `pro`：Google AI Pro（5 TB）各 SKU，含 `5tb.m` 别名（标为非标准档，见 §3.3 末条）。
  - `ultra`：Google AI Ultra（30 TB / 20x）主线 SKU；另含"30 TB 存储（含 20x Ultra）"`30tb.m`，标为非标准档并给出 Ultra 主线兜底价。
  - `storage`：按 `cap` 只取对应容量的纯存储 SKU（不含 AI 套餐）。
- `elig=existing` 时：**直接剔除**所有 `intro !== null` 的报价以及拉新/促销 SKU，只保留常规无优惠报价。
- 历史快照、源数据异常记录一律不进入决策器。

### 3.3 成本计算（数据层纯函数，必须单测全覆盖）

设计划时长 M 个月，返回**在这 M 个月内实际支付的现金总额（CNY）**：

| 报价类型              | 计算                                                                    |
| --------------------- | ----------------------------------------------------------------------- |
| 月付，无优惠          | `renew × M`                                                             |
| 月付，付费首期 k 个月 | `intro × min(M, k) + renew × max(0, M − k)`                             |
| 月付，免费试用 t 个月 | `renew × max(0, M − t)`                                                 |
| 年付，无优惠          | `renewYear × ceil(M / 12)`                                              |
| 年付，付费首期 k 年   | `Y = ceil(M / 12)`；`introYear × min(Y, k) + renewYear × max(0, Y − k)` |
| 年付，免费试用 t 个月 | `M ≤ t ? 0 : renewYear × ceil((M − t) / 12)`                            |

- **精度**：先在原币内累加总额，再一次性换算为 CNY；排序使用未舍入值，展示时保留 2 位小数。
- 派生：`monthly = total / M`；`perPerson = total / n`（及人均月均）。
- 账单时间轴按 M 截断；若优惠期 k > M，补充说明"优惠共 k 个月，其后恢复续费价"。
- 年付且 M = 3：照常计算（需一次付满 1 年），卡片与列表标注"需一次付 12 个月"。
- 每个地区取该产品线下 `total` 最小的报价作为该地区的"最优方案"；并列时优先：无首期优惠 > 非拉新 SKU > 月付 > SKU 字典序。
- 期数、试用时长、账期全部复用数据层现有解析（试用以 SKU 编码时长为准，付费首期以中文条款期数为准），不得在 UI 重新解析。
- **非标准/拉新判定**统一放在数据层（单一函数 + 测试）：覆盖所有 `intro !== null` 的报价，`.acq`、`_ip`/`ip_`/`ip.`（如 `1month_ip.0.49`）、`_eft` 等后缀，以及 `5tb.m`、`30tb.m` 这类别名 SKU。命中时标注"特定入口/拉新优惠，可能并非人人可见"，并给出该地区**同一 need 的主线常规方案**（无优惠、非别名）作为兜底价。

### 3.4 输出

**对比基准**：取 `base` 地区在当前 `need`（及 `cap`）与 M 下的**常规无优惠最优方案**，并注明方案名；基准地区无活跃报价时隐藏差额。

**三张推荐卡**（桌面三列；移动端第 1 张完整展示，2、3 张为紧凑摘要行，点开展开）。三张卡都在当前筛选（含 `easy`）后的候选中产生：

1. **最省**：在当前筛选下 `total` 最低的地区方案。
2. **稳妥**：`access = easy`（官方礼品卡可用）的地区中最低者。若与"最省"相同，显示"最省方案本身即礼品卡可用地区"，并在存在 ≥ 2 个候选地区时展示该组第二名，否则隐藏此卡。差额文案：`{M} 个月多 ¥X`（`n > 1` 时为人均每月多 ¥X）。
3. **首付最低**（仅 `elig=new` 且与前两张不同才显示）：第一笔实付金额最低的方案（"今天只要 ¥X"）。并列（如都是 ¥0 试用）时依次按：试用月数降序 > M 个月总价升序 > 折月续费价升序 > 地区码。优惠结束后的续费按全站统一分级展示：试用转正或 ≥10× 用朱砂色，≥1.2× 且 <10× 用琥珀色，其余用次要文字色。付费优惠跳涨 ≥1.2× 时显示倍数。若其 M 个月总价高于"最省"卡，标注"仅适合在优惠期内取消"。

**低差价提醒**：当"最省"相对基准的差额折合每年 < ¥100（多人时人均每月 < ¥2），在最省卡上附注"与 {基准} 差价较小，换区前请评估切换成本"。

每张卡包含：国旗 + 地区 + 付款标签（礼品卡可用 / 需当地支付 / 未确认）+ USD 计价标记；方案名（如"年付 · 首年 7.5 折"）；大字 `月均 ¥xx.xx`（多人时为人均）；`M 个月共 ¥xxx`；`比 {基准} 省 ¥xxx（−xx%）`（若更贵则如实显示"多 ¥xxx"）；**账单时间轴**（如"第 1–3 月 ¥1.32/月 → 第 4–12 月 ¥114.46/月"或"今天付 ₺6,499.99，次年 ₺8,699.99"，带原币，便于用户知道需要准备多少当地货币余额）；"订前检查"展开区（`<details>`）：付款方式说明 + 来源链接、首期资格提示、家庭共享提示（来自 `products.json`）、取消续费提示，以及指向避坑指南对应文章的链接。

**同条件地区排行**（卡片下方）：默认显示前 10，可展开全部。列：`排名 ｜ 地区（付款标签、USD 标记） ｜ 最优方案 ｜ M 个月总计（月均） ｜ 较基准 ｜ 优惠后续费 ｜ 操作`。用 `*` 标记特定入口，表下解释含义。移动端为两行列表，方案名保持单行，无横向滚动。

**跨区前须知**（3 条要点 + 链接到 `/guide`）：独立外区账户与更改地区的前提、首期优惠只限首次订阅、家庭共享须同地区。

**分享**：`复制方案链接`、`复制文字摘要`（一段适合发到聊天群的纯文本：需求、时长、人数、最省/稳妥方案、价格观测日期、链接）。

### 3.5 边界与提示

- `n > 1` 且产品不支持家庭共享（依 `products.json`）：不计算人均，提示原因。
- 筛选后无候选：明确说明并给出放宽建议。
- 付款标签 `unknown` 的地区照常参与"最省"计算，但不进入"稳妥"。
- 所有金额旁可悬停/点开查看换算明细（原币、汇率、日期）。

## 4. 信息架构

| 导航       | 路由                              | 说明                                                                                                                          |
| ---------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 方案推荐   | `/`                               | 决策器（§3）                                                                                                                  |
| 国家/地区  | `/countries`、`/countries/[iso3]` | 地区决策档案（§5）                                                                                                            |
| 全量比价   | `/matrix`                         | 原矩阵（保留 v1 能力与三口径切换）+ 免费试用一览（从首页移来）；档位页 `/tiers/[id]` 保留为不在导航中的深链页                 |
| 避坑指南   | `/guide`、`/guide/[slug]`         | 渲染 `src/content/guide/`                                                                                                     |
| 数据与更新 | `/data`                           | 合并原 `/changes` 与 `/rates`：数据时效、计算口径、变动记录、汇率表、免责声明。`/changes`、`/rates` 重定向到 `/data` 对应锚点 |

- 首页不再有 14 张档位卡、速览条与全局三口径条（三口径切换仅保留在 `/matrix` 与 `/tiers/*`）。
- `/tiers/[id]` 顶部加引导条："按你的时长和人数重新计算 →"（链接到 `/?need=…`）。
- sitemap、canonical、JSON-LD 随路由更新；被重定向的旧路由不进 sitemap。

## 5. 地区决策档案 `/countries/[iso3]`

自上而下：

1. 档案头：国旗、名称、币种（USD 计价标记）、**付款条件**（礼品卡是否官方可用、官方付款方式类别、来源链接与复核日期）。
2. **该区各产品线最优方案**：4 行（Plus / Pro / Ultra / 存储 2TB），按默认条件（首次订阅、12 个月、1 人）给出最优方案、月均、与美国对比，以及"在决策器中查看 →"（链接 `/?need=…&focus={iso3}`：在排行中定位并高亮该地区，不改变对比基准）。
3. 优势：该区在哪些产品线进入全球前 3（按上述默认条件）。
4. 完整 SKU 表含历史快照开关。同一商品、账期、优惠条款、币种及首期和续费原币金额均相同的 SKU 合并展示。活跃报价和历史快照分组展示。展开可查看并逐个复制全部 SKU，组内任一 SKU 达到全球最低则标记整组。

## 6. 数据时效（全站）

- Header 元信息显示 `价格 今天`、`价格 昨天` 或 `价格 N 天前`，后接 ` · 汇率 MM-DD`，点击到 `/data`。相对日期在客户端按 UTC+8 的日历日计算（`metadata.pricesObservedAt`；源数据无时区，按 UTC+8 解析）。静态页面可能被缓存，不能只在构建时计算。
- 状态：价格观测 ≤ 7 天正常；7–30 天在决策器结果上方显示一行琥珀色提示"价格观测于 N 天前，下单前请以 App Store 显示为准"；> 30 天在页面顶部显示朱砂色横幅"价格数据已超过 30 天未更新，仅供参考"，并将推荐卡措辞从"最省"弱化为"按 {日期} 价格最省"。
- 依据：Apple 订阅价格调整频率低（通常一年数次），因此不采用小时级阈值。

## 7. 性能与工程

- 决策器为 Preact island，SSR 输出默认参数的结果（首屏无需等待 JS）；水合后按 URL/localStorage 参数重算。props 只传紧凑数值（每条候选：地区、SKU、need/cap、账期、首期原币/期数/试用月数、续费原币、币种、非标准标记、方案文案 key；外加汇率表与日期、价格观测时间、地区元数据：付款分级、USD 计价标记），整体 HTML < 250KB，新增 JS < 20KB gzip。
- 依赖的数据文件：`src/data/country-meta.json`（付款分级 `access`）、`src/data/products.json`（家庭共享等权益）、`src/content/guide/`（指南），均已在仓库中（见 `docs/country-meta.md`）；汇率在构建时由 Frankfurter 获取（见 `docs/data-source.md`）。
- 计算函数放在 `src/lib/data/`（与 SSR 共用），覆盖 §3.3 全部分支与 §3.3 并列规则的单测。
- 其余页面保持零框架 JS。

## 8. 本版不做

礼品卡溢价估算（缺乏可靠依据，会误导）、价格历史曲线、变动推送（RSS/Telegram）、网页端价格对比、多国并排对比器、用户账号。

## 9. 验收

- [ ] §3.3 每种报价类型在 M = 3/12/24 下的总额与手算一致（单测 + 抽查 3 个真实地区）。
- [ ] `existing` 时没有任何首期价参与计算。
- [ ] 多人时显示人均，不支持共享的产品给出提示。
- [ ] 稳妥卡只来自 `access = easy`；`unknown` 不进入稳妥卡。
- [ ] 拉新 SKU 有标注且给出常规兜底价。
- [ ] 各 need 的候选集只含对应商品（选 `storage` + `cap=10tb` 时不会出现 30 GB/100 GB 等）。
- [ ] 对比基准为基准地区的常规无优惠方案；首付最低卡在 ¥0 并列时按规定顺序破局；低差价提醒按阈值出现。
- [ ] 时效三态在 3 个时间点（模拟）下表现正确。
- [ ] `/changes`、`/rates` 重定向生效；导航 5 项；`/tiers/*` 有回到决策器的引导。
